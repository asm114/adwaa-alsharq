# فحص OAuth على Windows

الحزمة `Adwaa-OAuth-Local-Check.zip` تحتوي خمسة سكربتات فقط، بلا بيانات اعتماد.
تحتوي نسخة `check_oauth_local.py` من Commit
`8402355a7e818df98a64212ffc51aee9b97dc04b`.

فك الملفات مباشرة داخل `C:\Adwaa-Backup`، بجوار ملف العميل الأصلي
من Google (يحتوي قسم `installed` أو `web`) و`drive_oauth_token.json`
(يحتوي `refresh_token`). انقر مرتين على `Run-OAuth-Check.cmd`.
يلزم Python 3 حديث مع Python Launcher (`py`) واتصال إنترنت لتثبيت المكتبات.
الحزمة لم تُختبر على جهاز Windows فعلي؛ اختبارات الملفات والنقل اصطناعية.

المشغّل ينشئ `.oauth-check-venv` للمكتبات فقط. لا يُعدّل ملفات التفويض أو
يحفظ رموزًا جديدة. جميع بيانات التفويض تقرأ إلى الذاكرة، وتُرسل فقط إلى
`https://oauth2.googleapis.com/token` مع TLS ومنع redirects. لا يصل إلى ملفات
Drive ولا إلى GitHub أو Supabase. المخرجات رمز تشخيص ثابت فقط. لا تستخدم
تسجيل HTTP خارجيًا أو أدوات اعتراض تفك TLS أثناء الفحص.

`OAUTH_LOCAL_OK` نجاح التفويض والنطاق، وليس إثبات تطابق أسرار GitHub.
`LOCAL_CLIENT_BINDING_MISMATCH` اختلاف بيانات العميل بين الملفين.
`LOCAL_CLIENT_FILE_AMBIGUOUS` وجود أكثر من ملف عميل؛ يتوقف بدل التخمين.
`LOCAL_PYTHON_SETUP_REQUIRED` غياب مشغّل Python أو فشل إنشاء البيئة.
`LOCAL_DEPENDENCY_SETUP_FAILED` تعذر تثبيت المكتبات.
بقية رموز OAuth لا تحتوي نص استجابة Google أو بيانات اعتماد.

لا ترفع ملفات JSON أو مجلد البيئة المحلية إلى GitHub. الحزمة مخصصة للفحص
فقط، ولا تشغّل النسخ أو الاستعادة أو الجدولة أو إنشاء المجلدات.

## مزامنة المجموعة المحلية المتحققة إلى GitHub

بعد نجاح الفحص، يمكن تشغيل `Sync-GitHub-OAuth.cmd`. يتطلب GitHub CLI الرسمي
(`gh`) مثبتًا ومسجل الدخول إلى حساب مخوّل بتحديث أسرار Environment. لا يبدأ
تسجيل الدخول تلقائيًا. يعيد فحص Google أولًا؛ عند النجاح فقط يرسل الأسرار
الثلاثة إلى `asm114/adwaa-alsharq`، Environment `production-backup`، عبر stdin
لـ`gh secret set`. لا حافظة ولا قيم في command line أو ملفات إضافية أو سجلات.
هذا المسار يحدّث الثلاثة من المصدر المتحقق نفسه، ولا يولد أو يدوّر أي اعتماد.
لا يشغّل Actions أو يغيّر متغيرات أو حماية البيئة.

`GITHUB_OAUTH_SYNC_OK` يعني قبول تحديث الثلاثة، وليس نجاح فحص runner.
`LOCAL_GITHUB_CLI_REQUIRED` يلزم GitHub CLI الرسمي؛
`LOCAL_GITHUB_LOGIN_REQUIRED` يلزم تسجيل دخول CLI رسمي بصلاحية الأسرار.
`GITHUB_OAUTH_SYNC_FAILED` رفض أول تحديث؛
`GITHUB_OAUTH_SYNC_INCOMPLETE` قد تكون المجموعة محدثة جزئيًا: لا تشغّل
Actions؛ أصلح الصلاحيات ثم أعد نفس المزامنة. تحديث المجموعة ليس معاملة ذرية.

## السر الذي ظهر سابقًا في صورة — بوابة قبل الإنتاج

المزامنة ليست بديلًا عن استبدال Client Secret المكشوف. لا تفعّل النسخ اليومي
قبل استبداله رسميًا في Google Cloud. عندما يتيح العميل وجود سرين نشطين، أضف
سرًا جديدًا دون تعطيل القديم، وحدّث الملف المحلي خارج Git ثم افحص تجديد الرمز.
لا تفترض أن Refresh Token القديم يعمل بعد التغيير: إن رفضه Google، أعد تفويض
العميل نفسه رسميًا بنطاق drive.file وoffline access واحفظ الرمز الجديد محليًا.
زامن المجموعة الجديدة، ثم أثبت نجاح فحص runner وDrive قبل تعطيل السر المكشوف.
إن لم يسمح Google بسرين، حضّر جميع التحديثات ثم استخدم نافذة صيانة قصيرة لمسار
النسخ فقط، دون تغيير اعتماد آخر أو كلمة مرور قاعدة البيانات. لا تستخدم OAuth
Playground إلا بإعداد عميلك الخاص ونطاقه المقيد. لا تتخلص من مفاتيح تشفير النسخ
القديمة؛ تدوير OAuth لا يتطلب تغيير مفاتيح تشفير النسخ.

## تصحيح سر Core من المفتاح الأصلي المحفوظ

`Adwaa-Core-Key-Sync.zip` حزمة مستقلة تحتوي `Sync-Core-Key.cmd` و
`sync_core_key.py` فقط. لا تحتوي مفتاحًا أو بيانات عميل، ولا تعدّل حزمة OAuth.
فكها داخل `C:\Adwaa-Backup` وانقر `Sync-Core-Key.cmd`. اختر من نافذة Windows
ملف **مفتاح Core الأصلي المحفوظ** وأكد هويته محليًا. لا تختَر ملف Portal.
يتطلب Python 3 الرسمي مع tkinter وGitHub CLI المسجل الدخول، وهما لا يثبتان
تلقائيًا هنا. نجحت اختبارات الملفات والمزامنة ببيانات اصطناعية؛ واجهة Windows
لم تُختبر على جهاز Windows فعلي.

يقبل ملف نص Base64 لمفتاح 32 بايت، أو JSON فيه الحقل الصريح
`BACKUP_CORE_ENCRYPTION_KEY`؛ يرفض target=portal وhex والملفات متعددة القيم
غير المهيكلة. يزيل BOM ونهاية السطر الخاصة بتنسيق الملف فقط؛ لا يغيّر البايتات
العشوائية ولا يولد أو يستبدل مفتاحًا من عنده. لا يمس الملف الأصلي ولا ينشئ
نسخة إضافية من المفتاح. لا ينسخ شيئًا إلى الحافظة أو Git ولا يطبع بصمة المفتاح.

بعد التحقق يرسل القيمة إلى GitHub CLI عبر stdin، لسر واحد فقط:
`BACKUP_CORE_ENCRYPTION_KEY` داخل production-backup في asm114/adwaa-alsharq.
لا يغيّر Portal أو OAuth أو كلمات المرور، ولا يشغّل Actions أو نسخًا أو استعادة.
`GITHUB_CORE_KEY_SYNC_OK` يعني قبول تحديث السر فقط؛ يلزم فحص runner محمي
لإثبات صلاحيته هناك. `LOCAL_CORE_KEY_FILE_INVALID` يعني أن الملف لا يجتاز
الصيغة؛ لا تتخلص من الملف ولا تولّد مفتاحًا جديدًا. إن لم يوجد المفتاح الأصلي
توقف؛ لا تعتمد مفتاحًا بديلًا أو بيانات مقتطعة من المحادثة.
