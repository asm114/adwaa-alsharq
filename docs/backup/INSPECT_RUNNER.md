# فحص a6b4881 دون تسجيل workflow على main — مسودة محلية

## لماذا هذا المسار

workflow_dispatch وrepository_dispatch وworkflow_run ليست حلولًا لتجاوز متطلبات التسجيل على الفرع الافتراضي. ولا تغير إعادة تشغيل workflow قديم SHA أو شيفرة ذلك التشغيل. لا يجوز استخدام run قديم للتهيئة كأنه فحص a6b4881.

يدعم GitHub حدث push على فرع موجود دون نسخ الملف إلى main. لذلك تُجهز مسودة backup-inspect-once.yml على فرع PR #165 فقط، كمنسق محدود. لا تشغيل/رفع/Commit في مرحلة التجهيز هذه.

## هويتان منفصلتان لا يجوز الخلط بينهما

1. كود الفحص المستهدف ثابت حرفيًا على a6b488132a203c45ca27c5f6d4f6f7b0f1a14d4e في checkout وفي اختبار git rev-parse HEAD. يجب أن يطابق Repository Variable الحالي BACKUP_SETUP_APPROVED_SHA هذا الهدف، وBACKUP_SETUP_MODE=inspect-drive.
2. github.sha هو Commit جديد يضيف المنسق نفسه، وليس a6b4881. يتطلب BACKUP_INSPECT_RUNNER_APPROVED_SHA مساويًا له تمامًا. اعتماد الهدف لا يعتمد المنسق تلقائيًا. لا يُقبل ref متحرك أو SHA من نص shell غير موثوق.

غياب اعتماد المنسق أو اختلاف أي شرط يتخطى المهمة قبل إتاحة الأسرار. وبعد اجتياز الشروط تبقى موافقة production-backup لكل هدف إلزامية. لا bypass أو تعديل حماية أو دمج main أو تغيير الموقع. الأسرار في خطوة الفحص فقط؛ لا بيانات اعتماد قواعد البيانات أو Storage.

## ما ينفذه

inspect-drive ثابت فقط لهدفَي core وportal، باستخدام الدالة الموجودة في a6b4881. لا init-drive أو preflight أو backup أو restore أو حذف. كل بوابات الكتابة/الجدولة في هذه المهمة false. تجديد OAuth اتصال بخدمة الرموز، وليس إنشاء ملف أو تعديل أسرار GitHub. لا تعويض تلقائي بنطاق واسع إذا لم يؤكد Google drive.file.

## الخطوات بعد الموافقات — لم تُنفذ

1. يوافق المالك على إنشاء ورفع Commit المنسق واختباراته فقط إلى فرع PR #165.
2. نفحص CI ونعطي SHA المنسق الكامل. يبقى التشغيل متخطى ما لم يكن معتمدًا.
3. يضيف المالك Repository Variable الجديد BACKUP_INSPECT_RUNNER_APPROVED_SHA بالقيمة المحددة، دون تغيير اعتماد الهدف a6b4881 أو تكرار إعداد الأسرار.
4. بموافقة تشغيل منفصلة يُعاد تشغيل تشغيل المنسق الخاص بذلك SHA نفسه من Actions، ثم يوافق مراجع production-backup. إعادة تشغيل نفس الحدث تحفظ github.sha للمنسق؛ checkout يظل a6b4881. لا يرفع Commit فارغ ولا يحرك ref قديمًا ولا يستخدم force-push.
5. تراجع النتائج/رموز التشخيص والمجلدات دون تعديلها. لا يُعاد init-drive عند فشل الفحص أو غياب مجلد، ولا تُغير الأسرار دون قرار منفصل.
