# الإعداد اليدوي المحدود — PR #165

هذا التغيير يجهز workflow_dispatch فقط لتهيئة مجلدي Drive الخاصين بـCore وPortal. لا تشغيل عند push أو schedule أو pull_request، ولا preflight أو backup أو restore أو حذف. كل هدف يبقى خلف موافقة production-backup، والسكربت يحتفظ باشتراط BACKUP_DRIVE_SETUP_APPROVED وBACKUP_COST_APPROVED؛ اعتماد الإعداد لا يمنح صلاحية نسخ الإنتاج.

## هوية الالتزام والموافقة

الطلب اليدوي يحدد operation=init-drive وapproved_sha الكامل (40 خانة). يجب أن يطابق approved_sha قيمة github.sha للفرع المحدد ومتغير المستودع BACKUP_SETUP_APPROVED_SHA. يجب أيضًا أن يكون BACKUP_SETUP_MODE=init-drive، وأن يكون المصدر المستودع asm114/adwaa-alsharq والفرع ops/encrypted-daily-backup-20261024. أي اختلاف يجعل المهمة متخطاة، ولا يتم تسجيل أو تنفيذ عملية Google. checkout مثبت على github.sha نفسه، وليس رأس فرع متحرك أو SHA من أمر shell.

هذه متغيرات **مستودع** لأن شرط job يُقيّم قبل توافر متغيرات البيئة. أسرار Google تبقى في بيئة production-backup المحمية، ولا تدخل workflow inputs أو السجلات. لا أسرار PostgreSQL أو Storage في هذا الملف. اعتماد البيئة خطوة مستقلة لكل target؛ لا يوافق السكربت عليها آليًا.

## قيد GitHub والتسجيل على main

يتطلب workflow_dispatch وجود ملف workflow على الفرع الافتراضي حتى يظهر/يقبل GitHub التشغيل اليدوي. رفع التعديل إلى PR لا يسجل الملف على main ولا يكفي لإثبات إمكانية dispatch. لا يُعاد تشغيل push القديم للتحايل على هذا القيد.

تسجيل الملف على main يحتاج **تغييرًا منفصلًا معتمدًا** ومراجعة أثره على Vercel وأي نشر Git تلقائي؛ غياب تعديل واجهة لا يضمن أن push إلى main لن ينشرها. لا دمج PR #165 كاملًا أو cherry-pick له بلا مراجعة. لا يُسجل workflow أو تُعدل متغيرات الاعتماد أو يُرسل dispatch أو تُعتمد البيئة ضمن هذه الجولة. بعد تسجيل الملف المعتمد لاحقًا، يمكن اختيار فرع PR المدقق وتحديد SHA المطابق المعتمد، ثم مراجعة مهام البيئة قبل الموافقة.

آخر ملاحظة مؤكدة أثناء القراءة: المحاولة الثانية عند SHA 9fbd55dec7cb345dca270955d7a24a8948d7fd65، event=push، ومهمتا initialize-drive لـCore وPortal تنتظران production-backup؛ read-only-preflight متخطاة. لا دليل يحدد أي جزء من شرط المحاولة الأولى فشل تاريخيًا. إعادة قراءة متغيرات المستودع ليست مخولة من الوصول المتاح سابقًا (403)، لذلك لا نخمن قيمها.

تعديل الملف لا يغير تعريف التشغيل المعلق السابق ولا يعتمد بيئته أو يلغيه. يجب مراجعة SHA ذلك التشغيل مستقلاً؛ اعتماد SHA أحدث لا يعني أن تشغيلًا قديمًا صار ينفذ الشيفرة الجديدة.

## دليل الاختبار وحدوده

اختبارات الشرط تتحقق من الحالة الصحيحة، وترفض push/schedule والعمليات الأخرى والفرع أو المستودع المخالف وSHA غير المطابق أو المفقود أو المتغير غير المعتمد. اختبارات الملف تثبت بقاء حماية البيئة وcheckout المثبت واعتمادي setup/cost وغياب بيانات دخول DB والجدولة والحذف. تعمل الاختبارات المصطنعة على Core وPortal؛ نتائج CI تُنسب إلى الالتزام الجديد في PR.

لا تشغيل Google فعلي أو نسخة إنتاجية أو تسجيل main نُفذ للتحقق من هذا التغيير. اجتياز CI لا يعني أن workflow_dispatch صار مسجلاً على الفرع الافتراضي أو أن الموافقات والأسرار الخارجية جاهزة.

التحقق المحلي لهذه الجولة: 47 اختبارًا ناجحًا لـCore و47 لـPortal، مع نجاح تحليل YAML لكل ملفات workflows وgit diff --check. لا تُعد هذه النتائج تشغيل init-drive فعليًا؛ CI على الالتزام المرفوع يعيد الاختبارات والاستعادة المصطنعة المستقلة لكل هدف.
