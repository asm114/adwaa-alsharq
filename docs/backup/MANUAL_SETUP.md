## إضافة محلية مقترحة: فحص Drive للقراءة فقط

أضيفت عملية `inspect-drive` إلى workflow_dispatch وجُعلت الافتراضية، مع مهمة مستقلة للهدفين. لا تُنفذ initialize-drive عند اختيارها؛ يلزم توافق `inputs.operation=inspect-drive` وRepository Variable `BACKUP_SETUP_MODE=inspect-drive`، ومطابقة `inputs.approved_sha` و`BACKUP_SETUP_APPROVED_SHA` مع `github.sha`، ونفس الفرع والمستودع وموافقة `production-backup`.

الأمر الثابت هو `python tools/backup/backup.py inspect-drive`: يجدد رمز الوصول باستخدام OAuth القائم، ويرفض نطاقًا غير مؤكد أو أوسع من drive.file، ويتحقق من الحساب، ويبحث عن علامة المشروع فقط. عند وجود مجلد واحد يتحقق من ملكيته وخصوصيته وهويته بالقراءة؛ عند غيابه يرجع count=0 دون إنشاء، وعند تكرره يفشل برمز آمن. المخرجات تقتصر على مرجع المشروع ونتيجة المطابقة وعدد المجلدات ومعرفاتها غير السرية؛ لا بريد أو أسماء ملفات أو رموز OAuth.

تستخدم المهمة أسرار Google الثلاثة فقط. تُفرض داخل هذه المهمة أذونات setup/execution/restore/schedule/retention=false؛ لا تغيير لمتغيرات البيئة المخزنة ولا أسرارها. يبقى اعتماد التكلفة وموافقة المراجع مطلوبين. لا استدعاء init-drive أو قاعدة بيانات أو رفع/حذف ملف. تجديد OAuth اتصال لخدمة الرموز، وليس تغييرًا لبيانات Drive أو لتفويض GitHub المخزن.

يحافظ الكود على عملية init-drive السابقة للموافقة المنفصلة، لكنه لا يختارها تلقائيًا أو عند خطأ/غياب نتيجة الفحص. الفحص يحدد حالة التفويض والحساب والمجلدات الحالية، ولا يستعيد تفاصيل الخطأ التي حجبتها السجلات القديمة؛ لا ندعي تحديد السبب التاريخي إذا نجح الفحص الآن.

نجح محليًا 58 اختبارًا لكل هدف، مع فحص YAML وشروط الرفض عند تبديل العملية أو الفرع أو SHA أو repository mode، واختبارات غياب المجلد والتكرار والملكية وعدم إنشاء/حذف أو اتصال PostgreSQL، وحفظ رموز الخطأ الآمنة دون نص الاستثناء. لا Commit أو رفع أو تشغيل Workflow ضمن هذا التجهيز.

بعد اعتماد رفع التعديل، يُحدّث SHA المعتمد وmode إلى inspect-drive، ثم يُطلب تشغيل يدوي منفصل ويوافق المراجع على مهمة الفحص فقط. لا ترفع/تشغل النسخة القديمة init-drive على أمل أنها ستفحص فقط. قيد تسجيل workflow_dispatch على الفرع الافتراضي يظل قائمًا؛ لا دمج أو تسجيل main أو تجاوز حماية هنا.

## هوية الالتزام والموافقة

الطلب اليدوي يحدد operation=init-drive وapproved_sha الكامل (40 خانة). يجب أن يطابق approved_sha قيمة github.sha للفرع المحدد ومتغير المستودع BACKUP_SETUP_APPROVED_SHA. يجب أيضًا أن يكون BACKUP_SETUP_MODE=init-drive، وأن يكون المصدر المستودع asm114/adwaa-alsharq والفرع ops/encrypted-daily-backup-20261024. أي اختلاف يجعل المهمة متخطاة، ولا يتم تسجيل أو تنفيذ عملية Google. checkout مثبت على github.sha نفسه، وليس رأس فرع متحرك أو SHA من أمر shell.

هذه متغيرات **مستودع** لأن شرط job يُقيّم قبل توافر متغيرات البيئة. أسرار Google تبقى في بيئة production-backup المحمية، ولا تدخل workflow inputs أو السجلات. لا أسرار PostgreSQL أو Storage في هذا الملف. اعتماد البيئة خطوة مستقلة لكل target؛ لا يوافق السكربت عليها آليًا.
