# خطة صيانة أضواء الشرق — 2026-10-23

## النطاق
نظام الإدارة الرئيسي فقط. بوابة العملاء مؤجلة. لا نشر ولا دمج قبل المراجعة.

## العطل المرصود
عند إنشاء عقد أو رسالة أو تعديل مبلغ في صفحة العميل، وأحياناً عند عمليات المالية، ينتظر النظام عدة ثوان ثم يظهر «فشل الحفظ». بعد إعادة فتح الصفحة تظهر العملية محفوظة. قد يشير ذلك إلى فشل تأكيد الحفظ أو مزامنة ما بعد الحفظ أو timeout؛ لا تفترض السبب دون تتبع.

## أولويات التنفيذ
1. تتبع مسار العملية من ضغط زر الحفظ حتى استجابة Supabase وتحديث الواجهة، بما في ذلك أخطاء الشبكة والاستثناءات والمهلات.
2. التمييز بين نجاح الكتابة وفشل عمليات ما بعد الحفظ. التحقق من وجود السجل عند غموض نتيجة الطلب، وعدم إعادة كتابة دفعات أو عقود مكررة.
3. معالجة حالات التحميل والأخطاء حتى تبقى صفحة العميل قابلة للاستخدام دون إعادة فتحها.
4. إضافة اختبارات انحدار للعقود والرسائل وتعديل مبالغ العميل وعمليات المالية، بما فيها الاستجابة المتأخرة والانقطاع بعد نجاح الكتابة وتكرار الضغط.
5. بعد إثبات استقرار الحفظ: إعادة تصميم responsive للجوال والآيباد والكمبيوتر، وتحسين لوحة المالية دون تغيير منطق الأرصدة.

## ضوابط
- لا تغيير للحجوزات التاريخية أو نظام التسلسل أو حساب الأرصدة أو ترحيل بيانات الإنتاج.
- لا اختبارات كتابة على بيانات الإنتاج.
- ابدأ بمراجعة أحدث main والاختبارات الحالية والإصلاحات السابقة.
- قدم تقرير سبب جذري، اختبارات ناجحة، وطلب مراجعة قبل الدمج أو النشر.
