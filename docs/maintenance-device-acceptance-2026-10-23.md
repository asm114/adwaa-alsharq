# قبول الأجهزة والخدمات قبل إغلاق بوابة الصيانة

هذه قائمة تحقق متبقية، **وليست نتائج اختبارات أُجريت**. التنفيذ على نسخة اختبار وبيانات مصطنعة مصرح بها؛ لا تجارب كتابة على الإنتاج ولا رسائل لعملاء حقيقيين.

## أجهزة Apple فعلية

| الاختبار | الإجراءات | معيار النجاح |
| --- | --- | --- |
| iPhone صغير وكبير | فتح نموذج الحجز والعميل والدفعات، ثم لوحة المفاتيح العربية والأرقام | الحقول وزر الحفظ قابلة للوصول، دون قيمة مبلغ مستنسخة أو ضغط مكرر |
| iPad رأسي وأفقي | تدوير الجهاز والنموذج مفتوح، واستخدام اللمس ولوحة مفاتيح خارجية إن توفرت | بقاء المدخلات، وعدم فقدان زر أو اختفاء بيانات أو تداخل نافذة |
| تعليق الشبكة الحقيقي | قطع الاتصال أثناء الحفظ ثم إعادته، وتأخير الطلب عبر وسيط اختبار | يعود التحكم، وتظهر النتيجة المجهولة، والتحقق لا يكرر قيدًا أو حجزًا |
| Safari والتبويب المستعاد | إغلاق وإعادة فتح التبويب بعد تمكين حماية الجهاز | لا تظهر بيانات محلية قبل التحقق من الوصول؛ يلزم فتح الخزنة لعبارة الاسترداد |
| PWA الموجودة | الفتح من الشاشة الرئيسية وsafe areas والانتقال للخلف والخلفية | لا كاش مالي نصي جديد، ولا عمليات مالية تُرسل من طابور offline |
| المستند والمشاركة الأصلية | توليد عقد اختبار وطباعته/معاينته، ثم مشاركة إلى جهة اختبار معتمدة | صحة العربية والطباعة والمستلم؛ إلغاء المشاركة لا يسجل إرسالًا مكتملًا |
| الذاكرة والتخزين المحدود | اختبار مفتاح خاطئ، إعادة فتح النسخة المحمية، ومحاكاة امتلاء مخزن الاختبار | لا حذف للأصل ولا إعادة إنشاء قيود، ورسالة واضحة مع قابلية الاسترداد |
| الخزنة القديمة | حماية localStorage وIndexedDB الموجودة على جهاز اختبار، ثم فتحهما بعد جلسة جديدة | تحقق فعلي من نسخة الاسترداد ومن عدم فقد مسودة قديمة |

## خدمات معزولة مطلوبة

- Supabase اختبار مستقلة مع حساب مدير وحساب غير مخول وJWT حقيقية من Auth، للتحقق من الدخول والخروج وتجديد الجلسة وRLS عبر SDK. لا حاجة لتزويد هذه الجلسة ببيانات إنتاج أو نسخ عملاء.
- Google Drive اختبار مصرح به لرفع/تنزيل/فحص ملف مصطنع؛ عدم اعتبار فشل المزامنة فشلًا لنسخة محلية متحقق منها.
- مشاركة/واتساب بجهة اختبار معتمدة عند اختبار الانتقال الأصلي. لا إرسال تجريبي لعميل قائم.

## شرط انتقال العملاء

اختبار PostgreSQL وREST أثبت أمان CAS بين النسخ الجديدة، وأثبت أيضًا أن النسخة القديمة ذات صلاحية UPDATE المباشر تستطيع تجاوز البروتوكول. قبل أي نشر، يُوثق إغلاق/تحديث جميع العملاء أو يُعتمد حارس خادمي بعد مراجعة منفصلة. لا يُغلق هذا الشرط اعتمادًا على refresh لجهاز واحد، ولا تُطبق تغييرات قاعدة الإنتاج ضمن هذه القائمة دون موافقة صريحة.
